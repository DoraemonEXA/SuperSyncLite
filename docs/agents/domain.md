# Domain documentation

SuperSync Lite uses one glossary for the server. When working on a sync concept, read its entry in the root `GLOSSARY.md` if present. Use the agreed term in specs, tickets, code, and tests. Create the glossary when the first term is settled.

Before proposing a design change, read any relevant architecture decision records in `docs/adr/`. If the proposal would revisit a decision, identify the record and explain what has changed. Record an agreed decision with a lasting trade-off in a numbered file such as `docs/adr/0001-<decision>.md`.
